# 小芽产品定位与完成标准

更新：2026-10-09。维护人：B 小芽项目负责人。用户在 A 总办秘书聊天明确的产品方向是本文件的依据；当前授权、任务负责人和执行状态仍以 [任务台账](coordination/TASKS.md) 为准。本文件描述长期方向与验收原则，不新增本轮开发授权。

## 产品是什么

小芽是专门制作小程序的 Coding Agent。用户用自然语言提出目标，Agent 理解已有项目，拆分工作，调用工具修改代码，读取真实构建和运行结果，在同一任务中纠正代码或检查计划，验证后交付。多轮执行和纠错是产品的基础能力。

最终使用场景：普通微信用户打开创作小程序，通过聊天创建应用，在手机上实际试用，继续对话修改，满意后按微信平台规则发布为独立的小程序。独立发布涉及账号、AppID、授权、审核等条件，尚未打通；不能把网页预览或 ZIP 导出当成已经实现该愿景。

当前保留 Electron 电脑版，作为制作、调试和项目管理入口。先验证可靠的持续制作能力，再推进微信创作端。沿用 PI Coding Agent SDK、Taro、React 和现有构建工具；产品方向对照 Codex、Claude Code 的工作方式，不等于更换技术栈或照搬其全部功能。

## 核心能力与验收要求

| 能力 | 产品必须表现出的行为 | 当前实现与缺口入口 |
| --- | --- | --- |
| 理解需求与规划 | 结合当前源码和长期需求安排步骤；用户修正优先；普通提问不强行改代码 | 已有项目需求记录和 Agent 上下文；复杂任务拆分效果需真实任务证明 |
| 持续需求记忆 | 多次修改、重开和恢复后仍记住目标、限制与变更；用户能查看及纠正 | 已有持久记忆，见 HARNESS-001；不声称无限上下文 |
| 工具执行与环境反馈 | 实际读写、编译、运行检查；工具错误回到同一会话，模型据此继续行动 | 已接 PI 原生工具结果链；当前读书任务暴露检查预算和定位反馈缺口，STUDIO-002 修复中 |
| 自主修复 | 区分代码缺陷、检查计划错误、运行故障与外部故障；读取证据后修正并复验 | 不允许盲选第一个元素、降低断言、手工追加任务冒充同任务纠错；分层预算 v2 尚待独立验收和新包实测 |
| 功能验收 | 用户要求对应实际交互与业务断言，当前源码通过后才能交付 | 已有浏览器工具和严格二维码检查；编译通过、部分子检查通过均不足以证明整个需求完成 |
| 中断与恢复 | 保存任务状态、已花预算和恢复入口；明确停止后不自动重试；崩溃不能返还已用资源 | 已有任务持久化与恢复；新预算的硬中断、旧任务兼容须相称回归 |
| 可见进度与控制 | 用户能看到正在执行、失败原因、待验证事项，并停止或显式继续 | 已有进度与停止入口；预览初始化时输入响应已有针对性证据，最终包仍需整体验收 |
| 版本与数据保护 | 修改失败保留旧可用版本；恢复代码不擅自清空业务数据 | 已有不可变版本与恢复；真实连续修改和导出仍需绑定具体版本检查 |
| 配置持续可用 | 模型配置安全保存一次，正常开发、CLI、重开及升级继续复用 | 当前正常 current 已保存并验证重开；同版本跨目录测试已过，实际新版本复用待新包验证 |
| 可复验交付 | 交付对应源码、产物和功能证据；确认缺陷留下负例与修复正例 | 已有用户轨迹测试与统一入口，见 [回归说明](studio-regression.md)；模拟与真实证据分别记录 |

这些是持续评估维度，不承诺任意应用都能成功。能力状态随版本变化，查看台账及对应工作包，不能把本表当作最新测试报告。

## 小程序特有的完成标准

1. 需求与版本一致：检查的是当前待交付源码，保留原始目标、约束和修改要求，不能为通过测试删减业务要求。
2. 双端构建有实际结果：H5 预览与微信产物分别检查。检测到官方工具时记录其编译结果；Taro 编译不等于官方模拟器或真机已通过。
3. UI 与业务有实际交互：在明确手机尺寸中输入、点击、刷新和读取结果；例如二维码要解码实际截图，读书进度要检查书籍、页数和比例的业务关系。
4. 连续修改保护历史：后续需求保留既有功能与项目数据，失败不覆盖已可用版本，恢复后还能继续制作。
5. 导出可追溯：ZIP 的源码和微信产物对应交付版本，结构可导入官方工具。游客 AppID、正式 AppID、模拟器、真机及发布状态明确区分。
6. 证据足以支持结论：记录实际版本、运行入口、模型/构建/浏览器是否真实、检查范围与失败。已实现、已测试、已交付和已验收分别陈述。

普通可修错误应在同一自然需求内反馈和处理。任务达到资源上限、用户停止或需要新的外部授权时，诚实停止并保存状态；不能用无限重试维持“自主完成”的表象。

## 当前一轮范围

STUDIO-002 继续处理桌面预览响应、配置一次保存、CLI 协同，以及真实工具反馈驱动的制作与验收。本轮读书进度失败是基础 Agent 执行链的缺口：同一会话确实收到了错误，模型也尝试纠正，但两次定位错误加一次成功子检查耗尽了旧检查额度，下一次检查被拒绝。修复需要保留业务门槛，同时让检查计划纠正有独立、有限、可恢复的额度；不能只替换某个按钮选择器。

当前 r1 包未包含分层预算 v2；开发者报告的局部通过尚不代表独立 QA、新包真实模型或 B 最终验收通过。后续按照 [STUDIO-002 工作包](coordination/work-packages/STUDIO-002.md) 完成冻结、独立回归、打包、真实同任务纠错与交付核查。原用户项目和失败记录保留。

本轮不新增微信端迁移、多用户服务、云数据库、登录支付、账号注册、付费服务或公开发布。长期方向中的这些条件由后续明确任务推进。

## 官方能力对照与复用选择

查阅日期：2026-10-09。下表是机制对照，不能作为第三方产品全部功能的列表。在线主分支文档可能比项目锁定版本更新，实施以本地 0.99.1 API 和测试为准。

| 官方依据 | 可借鉴或复用的能力 | 本项目选择与最小自建范围 |
| --- | --- | --- |
| [Codex 长任务实践](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex) | 持久目标、约束、里程碑、验证条件与状态，失败后先修复 | 借鉴可恢复的工作方式；产品内由项目记忆、任务状态和验收工具承担，不引入另一个 Agent 框架 |
| [Claude Code 工作机制](https://code.claude.com/docs/en/how-claude-code-works) | 收集上下文、工具行动、验证并根据结果调整；用户可中断 | 作为多轮执行与工具反馈的能力对照；不要求复制通用终端权限或全部扩展机制 |
| [PI 官方 SDK](https://github.com/pi-packages/earendil-works-pi/blob/main/packages/coding-agent/docs/sdk.md) / 本地同包 docs/sdk.md | 原生会话、工具调用、事件、持久 SessionManager、上下文压缩与受控重试 | 已采用 MIT 许可的 PI 0.99.1，复用既有依赖，无需替换；自建小程序工具、业务验收、任务预算与安全边界。官方仓库近期可访问，但不把活跃等同于长期维护保证 |
| [Taro 官方文档](https://docs.taro.zone/docs/) / 既有 Taro 4.3.0 | 统一源码生成 H5 和微信产物 | 沿用现有双端构建，不为 Agent 定位重新实现编译器；平台兼容和真实运行仍独立检查 |
| [Playwright 定位严格性](https://playwright.dev/docs/locators#strictness) / 现有浏览器工具 | 多匹配拒绝单目标操作，真实浏览器定位与交互 | 沿用 Playwright；自建有上限、无编辑值泄露的候选反馈和需求断言。宿主不自动替模型挑选按钮 |

Codex 和 Claude Code 在此是产品能力参考，不将其实现代码引入仓库，因此本轮没有它们的依赖成本或兼容迁移。现有 PI/Taro/Playwright 锁定依赖继续复用；新增依赖仍须单独核对许可证、维护与版本兼容。
